# 訂單管理系統｜GitHub Pages 互動原型

這是依據《訂單管理系統需求規格書_20261123 v1.0（2026-11-23）》製作的純前端展示原型。介面為繁體中文，可直接部署至 GitHub Pages。

## 已納入的展示範圍
- **角色切換（重要）**：老闆、財務、經理、專員、業務助理。依規格控制選單顯示及操作；老闆頁面可調整專員／業務助理的逐項權限。
- 客戶、供應商（工廠／貨運）、產品與圖面資料、產品價格歷史。
- 訂單建立／修改、訂單明細、客戶 PO、原始訂單附件名稱紀錄、客戶／供應商／產品下拉即時篩選與自動帶入。
- **新增資料分流**：輸入清單不存在的客戶、供應商或產品時，詢問是否加入主檔；有該類資料編輯權限者可建立主檔，無權限者只能將資料留在本張訂單，不會寫入主檔。
- 客戶選取後自動帶入寄送地址、付款地址及聯絡人；產品選取後自動帶入客戶料號、工廠料號、Description、圖面及訂單日期當時有效價格。
- 分批出貨、出口報單、匯率、多段運送、運費、付款方及追蹤狀態。
- 多輪檢驗、不合格重做欄位與檢驗結果。
- 客訴、責任歸屬、補發／退款／工廠折讓紀錄。
- 應收、應付、預付款、折讓、幣別匯率與月結歸屬欄位。
- 產品處理選項維護、停用、操作修改紀錄、提醒摘要。

## 尚未實作／正式環境限制
- 第三階段「新產品詢價與供應商報價」依需求文件階段規劃先不納入。
- GitHub Pages 是靜態網站，沒有 ASP.NET Core API、PostgreSQL、伺服器端權限驗證、排程寄信、雲端檔案儲存及備份。這些不能以純靜態頁面安全地實作。新版規格已不再列出 MFA、掃毒及 PDF 轉檔預覽要求。
- 本原型的資料存在瀏覽器 `localStorage`，角色切換是**操作流程展示**，不是安全機制；使用者可清除瀏覽器資料。正式上線須依規格建置後端 API 並在 API 層驗證權限。
- 附件欄位僅供輸入檔名示意，不會真的上傳至網站或其他雲端儲存空間。

## 部署到 GitHub Pages
1. 將此資料夾中的所有檔案上傳到 GitHub repository 根目錄（或設定的 Pages 資料夾）。
2. GitHub 專案進入 **Settings → Pages**。
3. 在 **Build and deployment** 選擇 **Deploy from a branch**。
4. Branch 選 `main`，資料夾選 `/ (root)`，按 Save。
5. 等待部署完成，使用 GitHub Pages 顯示的網址開啟 `index.html`。

不需要 Node.js、編譯或安裝套件。

## 操作提示
- 右上角「目前角色」可即時切換五種角色，觀察選單及新增／編輯能力變化。
- 老闆可進入「使用者與權限」調整專員及業務助理的逐項權限。
- 可新增、編輯資料；變更會保存在同一瀏覽器。重新整理不會消失。
- 若要回復初始展示資料，於瀏覽器開發者工具 Console 執行：`localStorage.removeItem('afcoDemoDB'); location.reload();`

## 規格依據
需求文件第 3 頁為角色權限矩陣；第 3 頁為角色權限矩陣與無權限者僅能將新資料用於單張訂單的規則；第 4–5 頁包含訂單下拉搜尋、自動帶入及「加入主檔／僅用本訂單」流程圖；第 6–8 頁包含出貨、檢驗、客訴、帳務、資安與階段規劃。
